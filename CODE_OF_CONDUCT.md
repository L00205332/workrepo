# Code of Conduct

## Why this exists

This project is built by people who care about doing technical work well and doing it honestly. This Code of Conduct sets out how we work together, so that everyone, whether a first-time contributor or a long-time maintainer, can take part without worrying about how they'll be treated.

It applies to everyone involved: maintainers, contributors, reviewers, and anyone opening issues or joining discussions.

## Our principles

### 1. Respect people
- Treat everyone with courtesy, regardless of background, experience level, nationality, language, gender, age, religion, disability, or any other personal characteristic.
- Assume good intent. Most disagreements come from different context, not bad faith.
- English may not be someone's first language. Be patient with phrasing and ask for clarification instead of mocking it.

### 2. Be honest and accurate
- Make technical claims you can support. If you're unsure, say so.
- Credit the work of others. Don't present someone else's code, design, or ideas as your own.
- Disclose conflicts of interest, such as a commercial relationship with a product or vendor you're recommending.
- Admit and correct mistakes openly. A fixed mistake is a contribution, not an embarrassment.

### 3. Critique the work, not the person
- Code review is about the code. Explain *why* something should change, and suggest how.
- "This query will do a full table scan on large datasets; an index on `x` would help" is useful. "This is lazy" is not.
- Accept feedback gracefully, and push back with reasons when you disagree.

### 4. Protect users and their data
- Never commit secrets, credentials, customer data, or personal information, including in examples, logs, screenshots, or test fixtures.
- Report security vulnerabilities privately (see [Security reporting](#security-reporting)), not in public issues.
- Don't contribute code that is deliberately malicious, hides its behaviour, or weakens security without clearly saying so.

### 5. Collaborate in good faith
- Keep discussions on topic and constructive.
- Respect maintainers' time: search before opening an issue, and give enough detail to reproduce a problem.
- Respect decisions once they're made, even if you argued for something else. You can reopen a topic with new information.

## Unacceptable behaviour

The following are not tolerated in any project space:

- Harassment, intimidation, threats, or stalking
- Insults, slurs, or derogatory comments about a person or group
- Sexualised language or imagery, or unwelcome advances
- Publishing someone's private information (such as their address, employer, or contact details) without their explicit permission
- Sustained disruption of discussions, reviews, or issues
- Plagiarism or knowingly submitting code you don't have the right to contribute
- Encouraging or ignoring any of the above

## Scope

This Code of Conduct applies in all project spaces, including the repository, issues, pull requests, discussions, wikis, and any chat channels linked to the project. It also applies when someone is representing the project elsewhere, such as at events or on social media.

## Reporting

If you experience or witness behaviour that breaks this Code of Conduct, please report it to:

**[CONTACT EMAIL]**

Include what happened, where (links if possible), and when. You don't need to be certain something is a violation to report it.

All reports are handled confidentially. The reporter's identity won't be shared without their consent, and there will be no retaliation against anyone who reports in good faith.

If a report involves a maintainer, they will step back from handling it.

## Security reporting

Please don't open public issues for security vulnerabilities. Report them privately via **[SECURITY CONTACT or GitHub private vulnerability reporting]** so they can be fixed before disclosure.

## Enforcement

Maintainers will review every report and respond in proportion to its seriousness:

| Level | When | Likely action |
|---|---|---|
| **1. Correction** | A minor or one-off lapse | A private note explaining the issue; a public correction if needed |
| **2. Warning** | A single serious incident or repeated minor ones | A formal warning, with clear consequences for further behaviour |
| **3. Temporary ban** | Serious or sustained violations | Removal from project spaces for a set period |
| **4. Permanent ban** | Harassment, threats, or a pattern of serious violations | Permanent removal from the project |

Maintainers may remove, edit, or reject comments, commits, issues, and other contributions that don't follow this Code of Conduct.

## Appeals

If you believe an enforcement decision was wrong, you can appeal by emailing **[CONTACT EMAIL]** within 30 days, explaining why. Appeals are reviewed by a maintainer who wasn't involved in the original decision where possible.

## Changes

This Code of Conduct may be updated over time. Significant changes will be noted in the repository's commit history.

## Acknowledgements
